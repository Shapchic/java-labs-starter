# Если личный репозиторий создан до появления ЛР 2–8

Обновление центрального template repository **не обновляет** ранее созданные личные репозитории. Не создавайте новый личный репозиторий и не переносите работу через PR в репозиторий преподавателя: так теряется история ваших лабораторных и смешиваются чужие решения с шаблоном.

## Однократное обновление личного репозитория

1. Закончите текущую работу и убедитесь, что ее PR принят и слит в `main`. Проверьте `git status`: не должно быть незакоммиченных изменений.
2. Скачайте обновленный шаблон отдельным каталогом через **Code → Download ZIP** на странице шаблона или клонируйте его рядом с личным репозиторием. Не распаковывайте архив поверх своего проекта.
3. Из обновленного шаблона скопируйте только каталоги `lab02`–`lab08` в корень личного репозитория. Если какой-либо такой каталог у вас уже есть и содержит вашу работу, **не заменяйте его**: покажите преподавателю или перенесите только недостающие файлы после сравнения.
4. В своем корневом `pom.xml` в секции `<modules>` добавьте `lab02`–`lab08` после `lab01`. Остальное содержимое своего `pom.xml` не перезаписывайте. В результате секция должна содержать восемь строк `<module>lab01</module>` ... `<module>lab08</module>`.
5. Из корня личного репозитория выполните `./mvnw test` (Windows: `.\\mvnw.cmd test`). До написания кода для новых работ эта команда проверяет лишь конфигурацию и существующие тесты, а не выполнение новых заданий.
6. Проверьте `git status`, затем добавьте только `pom.xml` и новые каталоги: `git add pom.xml lab02 lab03 lab04 lab05 lab06 lab07 lab08`. Убедитесь, что в индексе нет `target/`, файлов IDE и ваших локальных данных. Сделайте отдельный коммит `Add starter modules for labs 02-08` в своем `main` и отправьте его в **свой** репозиторий. Если прямые коммиты в `main` запрещены, сделайте отдельную техническую ветку и PR **внутри своего** репозитория.

После обновления каждую лабораторную по-прежнему выполняйте в отдельной ветке `lab/NN-...` и сдавайте отдельным PR в `main` **своего** репозитория. Не отправляйте решения в центральный шаблон.

## Если перенос вызывает ошибку

- `Could not find the selected project`: проверьте точное имя каталога и строку `<module>` в корневом `pom.xml`.
- `release version 25 not supported`: настройте JDK 25 для терминала и IDE.
- `nothing to commit`: убедитесь, что копировали каталоги в личный репозиторий, а не в скачанный шаблон.
- Есть уже измененные `lab02`–`lab08`: не выполняйте массовую замену; сохраните свои файлы и сравните только конфигурацию.
