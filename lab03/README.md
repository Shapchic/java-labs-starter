## 1. Архитектура решения и описание контрактов

### 1.1. Подготовительная часть (Расчет скидок)

Реализован расчет скидки с использованием паттерна «Стратегия» (Strategy pattern):

- **Интерфейс `DiscountPolicy`**:
  - Метод `double apply(double price)`: контракт применения скидки к переданной цене.
- **Класс `NoDiscount`**:
  - Реализует `DiscountPolicy`. Возвращает исходную цену без изменений.
  - Запрещает отрицательную цену (`price < 0` выбрасывает `IllegalArgumentException`).
- **Класс `PercentDiscount`**:
  - Реализует `DiscountPolicy`. Принимает процент скидки в конструкторе.
  - Процент валидируется в диапазоне `[0.0, 100.0]`. При выходе за границы выбрасывается `IllegalArgumentException`.
  - Формула: `price * (1.0 - percent / 100.0)`. Например, скидка 20% для цены 100 возвращает 80.
  - Запрещает отрицательную цену.
- **Класс `PriceCalculator`**:
  - Хранит поле интерфейсного типа `DiscountPolicy`.
  - Получает зависимость через конструктор (`PriceCalculator(DiscountPolicy discountPolicy)`), не инстанциируя конкретную политику самостоятельно (Dependency Injection).
  - Метод `calculatePrice(double price)` делегирует вычисление установленной политике.
  - Метод `changeDiscountPolicy(DiscountPolicy discountPolicy)` позволяет динамически заменять стратегию во время выполнения.

### 1.2. Обязательное задание (Вариант: Инженерия систем искусственного интеллекта)

Реализована система предобработки и нормализации признаков в ML-пайплайне:

- **Доменная модель `DataSample`**:
  - Представляет наблюдение данных с признаками и меткой класса.
  - Поля: `id` (`String` / `SampleId`), `label` (`String`), `status` (`SampleStatus`), `features` (`double[]`).
  - Все инварианты защищены (запрет `null`, пустых строк, защитное копирование массива `features.clone()` в конструкторе и getter).
- **Интерфейс `NormalizationStrategy`**:
  - Метод `double[] normalize(double[] values)`: контракт нормализации вектора вещественных чисел. Метод возвращает новый массив и гарантирует неизменяемость переданного входного массива.
- **Класс `MinMaxNormalization`**:
  - Масштабирует значения вектора в диапазон `[0.0, 1.0]`.
  - Формула: `(values[i] - min) / (max - min)`.
  - При равенстве всех элементов вектора (`max == min`) возвращает вектор из нулей.
- **Класс `MeanCenteringNormalization`**:
  - Центрирует вектор относительно его среднего значения: `values[i] - mean`.
  - В результате среднее значение результирующего вектора равно 0.
- **Класс `FeatureProcessor`**:
  - Хранит поле интерфейсного типа `NormalizationStrategy`.
  - Принимает стратегию через конструктор (`FeatureProcessor(NormalizationStrategy strategy)`).
  - Метод `process(double[] values)` выполняет нормализацию переданного вектора.
  - Метод `processSample(DataSample sample)` возвращает новый объект `DataSample` с нормализованными признаками без мутации исходного объекта.
  - Метод `changeStrategy(NormalizationStrategy strategy)` позволяет заменять стратегию на лету без изменения кода процессора.

## 2. Дополнительная часть

### 2.1. Третья стратегия: `ZScoreNormalization`

Реализована Z-score стандартизация вектора признаков:
- Вычисляет выборочное среднее $\mu$ и стандартное отклонение $\sigma$:
  $$\text{normalized}[i] = \frac{\text{values}[i] - \mu}{\sigma}$$
- После нормализации среднее значение равно 0, а дисперсия равна 1 (при $\sigma > 0$).
- При $\sigma = 0$ (все элементы одинаковы) возвращает вектор нулей.
- В модульных тестах наглядно продемонстрирована заменяемость стратегий: один и тот же входной вектор последовательно обрабатывается `MinMaxNormalization`, `MeanCenteringNormalization` и `ZScoreNormalization`, давая ожидаемые математические результаты без изменения класса `FeatureProcessor`.

## 3. Соблюдение контракта и принципов ООП

1. **Зависимость от абстракции (DIP / OCP):** Клиентские классы `PriceCalculator` и `FeatureProcessor` зависят только от интерфейсов `DiscountPolicy` и `NormalizationStrategy`, а не от конкретных реализаций.
2. **Отсутствие антипаттернов ветвления по типам:** В коде не используются операторы `instanceof`, методы `getClass()`, рефлексия или `if-else` цепочки по типам стратегий.
3. **Неизменяемость входных данных (Immutability):** Все стратегии создают и возвращают новые массивы, оставляя исходный входной массив нетронутым. В `DataSample` реализовано защитное копирование (defensive copying).
4. **Покрытие тестами:** Для каждой стратегии и компонента написаны модульные тесты, проверяющие штатную работу, граничные условия, константные векторы и валидацию входных параметров.
