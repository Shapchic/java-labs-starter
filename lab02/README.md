## 1. Описание инвариантов классов

Инвариант — это условие, которое остается истинным на протяжении всего жизненного цикла любого корректно созданного объекта.

### 1.1. Класс `BankAccount` (Подготовительная часть)

- **Инварианты состояния:**
  - `balance >= 0`: текущий баланс счета никогда не может быть отрицательным.
- **Инварианты операций:**
  - Конструктор `BankAccount(int initialBalance)`: начальный баланс `initialBalance >= 0`. При попытке передать отрицательное число выбрасывается `IllegalArgumentException`.
  - Метод `deposit(int amount)`: сумма пополнения должна быть строго положительной (`amount > 0`).
  - Метод `withdraw(int amount)`: сумма списания должна быть строго положительной (`amount > 0`) и не должна превышать текущий остаток (`amount <= balance`).
  - Прямой setter для `balance` отсутствует; изменение баланса возможно только через бизнес-операции `deposit` и `withdraw`.

### 1.2. Класс `ProjectTask` (Вариант: Программная инженерия)

- **Инварианты состояния:**
  - `id`: обязательное поле, не равно `null` и не пустое (после удаления пробельных символов `!id.isBlank()`). Неизменяемое (`final`).
  - `title`: обязательное поле, не равно `null` и не пустое (`!title.isBlank()`). Неизменяемое (`final`).
  - `status`: обязательное поле, не равно `null`. Принимает значения из перечисления `TaskStatus` (`NEW`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`).
  - `estimatedHours`: оценка трудоемкости в часах должна быть строго положительной (`estimatedHours > 0`).
- **Инварианты операций:**
  - Метод `changeStatus(TaskStatus newStatus)`: запрещает установку `null` в качестве статуса.
  - Метод `addEstimatedHours(int additionalHours)` / `increaseEstimatedHours(int additionalHours)`: принимает только строго положительное число часов (`additionalHours > 0`).
  - Поля закрыты (`private`), универсальные сеттеры (`setId`, `setEstimatedHours` и др.) отсутствуют.
  - Метод `isCompleted()` возвращает `true`, если и только если `status == TaskStatus.COMPLETED`.

## 2. Дополнительная часть

### 2.1. Идентификаторы как Value Objects (`TaskId` и `SampleId`)

Для идентификаторов задач и образцов реализованы классы-записи (`record`): `TaskId` и `SampleId`.

**Почему идентификатор представляет собой значение (Value Object):**
1. **Эквивалентность по состоянию, а не по идентичности ссылок:** два объекта `TaskId("TASK-1")` и `TaskId("TASK-1")` логически равны и взаимозаменяемы, независимо от того, созданы ли они в разных местах памяти. В `record` методы `equals()` и `hashCode()` автоматически генерируются на основе значений компонентов.
2. **Неизменяемость (Immutability):** объект значения не меняет свое состояние после создания. Все поля `record` неявно являются `private final`.
3. **Инкапсуляция валидации:** компактный конструктор гарантирует, что не существует невалидного идентификатора (`null` или пустая строка). Это предотвращает распространение ошибок по системе.
