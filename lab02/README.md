## 1. Описание инвариантов классов

Инвариант — это условие, которое остается истинным на протяжении всего жизненного цикла любого корректно созданного объекта.

### 1.1. Класс `BankAccount` (Подготовительная часть)

- **Инварианты состояния:**
  - `balance >= 0`: текущий баланс счета никогда не может быть отрицательным.
- **Инварианты операций:**
  - Конструктор `BankAccount(int initialBalance)`: начальный баланс `initialBalance >= 0`. При попытке передать отрицательное число выбрасывается `IllegalArgumentException`.
  - Метод `deposit(int amount)`: сумма пополнения должна быть строго положительной (`amount > 0`).
  - Метод `withdraw(int amount)`: сумма списания должна быть строго положительной (`amount > 0`) и не должна превышать текущий остаток (`amount <= balance`).
  - Прямой setter для `balance` отсутствует; изменение баланса возможно только через бизнес-операции `deposit` и `withdraw`.

### 1.2. Класс `DataSample` (Вариант: Инженерия систем искусственного интеллекта)

- **Инварианты состояния:**
  - `id`: обязательное поле, не равно `null` и не пустое (после удаления пробелов `!id.isBlank()`). Неизменяемое (`final`).
  - `label`: метка класса / целевой признак, не равна `null` и не пустая (`!label.isBlank()`). Неизменяемое (`final`).
  - `status`: обязательное поле, не равно `null`. Принимает значения из перечисления `SampleStatus` (`RAW`, `PROCESSED`, `READY`, `REJECTED`).
  - `features`: обязательный массив числовых признаков `double[]`, не равен `null`.
- **Защита целостности данных (Defensive Copying):**
  - Массив `features` копируется через `features.clone()` в конструкторе при создании объекта. Мутация переданного извне массива не влияет на внутреннее состояние объекта.
  - Метод доступа `getFeatures()` возвращает защитную копию массива `this.features.clone()`. Мутация возвращенного массива клиентом не нарушает состояние объекта.
- **Инварианты операций:**
  - Метод `changeStatus(SampleStatus newStatus)`: запрещает установку `null` в качестве статуса.
  - Метод `isReady()`: возвращает `true`, если и только если `status == SampleStatus.READY`.
  - Метод `calculateMean()` (и алиас `getAverageFeature()`): вычисляет среднее арифметическое признаков. Для пустого массива возвращает `0.0`.
  - Поля инкапсулированы (`private`), универсальные сеттеры (`setId`, `setFeatures` и др.) отсутствуют.
  - Класс не читает данные из консоли и ничего не печатает (separation of concerns).

## 2. Дополнительная часть

### 2.1. Идентификатор как Value Object (`SampleId`)

Для идентификатора образца данных реализован класс-запись (`record`): `SampleId`.

**Почему идентификатор представляет собой значение (Value Object):**
1. **Эквивалентность по значению, а не по ссылке:** два объекта `SampleId("SMP-1")` и `SampleId("SMP-1")` логически равны и взаимозаменяемы, независимо от места в памяти. В `record` методы `equals()` и `hashCode()` автоматически генерируются на основе значений компонентов.
2. **Неизменяемость (Immutability):** объект значения не меняет свое состояние после создания. Все поля `record` неявно являются `private final`.
3. **Инкапсуляция валидации:** компактный конструктор гарантирует, что не существует невалидного идентификатора (`null` или пустая строка). Это предотвращает распространение некорректных данных по системе.

### 2.2. Нормализация признаков без мутации состояния

Реализованы методы `normalize()` и `normalizeFeatures()`:
- Выполняют шкалирование признаков в диапазон `[0.0, 1.0]` (Min-Max нормализация).
- Возвращают **новый** экземпляр `DataSample` с нормализованным массивом признаков.
- Исходный объект `DataSample` остается неизменным, гарантируя соблюдение принципа неизменяемости (immutability) при обработке данных.
